# Доработка ролика SciTok

Ролик: 1080×1920. Сверху — анимация (стейдж 1080×1000), посередине субтитры, снизу говорящий аватар.
Сценарий, голос, аватар и субтитры уже готовы и **не меняются**. Твоя работа — верхняя часть:
каждая сцена получает свой шот с одной ясной метафорой, привязанный к словам диктора. Потом ролик
пересобирается локально (ключи, GPU и деньги не нужны: голос, аватар и видеовставки берутся из архива).

Все команды — из корня этого репозитория. Пути роликов — `videos/<имя>/`.
Если репозиторий только что склонирован из чата, сначала перейди в его папку (`cd scitok-reel-studio`);
прикреплённый архив передай в `scripts/import.py` по его пути.

## 0. Подготовка (один раз)

```bash
bash scripts/setup.sh          # python-пакеты, npm, Chromium; нужны python3, node >= 18, ffmpeg
```

Не держи репозиторий и ролики в папках, которые синхронизирует iCloud (Документы, Рабочий стол на macOS):
система выгружает файлы в облако, и рендер или чтение виснут с «Operation timed out».

## 1. Взять ролик

```bash
python3 scripts/import.py ~/Downloads/research-reels-<job_id>-debug.zip [имя]
python3 scripts/words.py videos/<имя>          # слова каждой сцены с временем + какие шоты были
```

`import.py` раскладывает архив и проверяет, что ролик целый. Если он пишет «!!» — скажи человеку:
- голос сцены обрезан — эту сцену придётся выкинуть (`"drop"` в `work/plan.json`) или перезапустить ролик на сайте;
- нет аватара — поставлена неподвижная заглушка из портрета;
- нет видеовставки — на её месте заглушка «ГЕНЕРАЦИЯ», эту сцену обязательно замени своим шотом.

Что смотреть сначала: `videos/<имя>/reel/contact_sheet.jpg` (кадр каждого шота) и `reel/reel.mp4`.
Суть статьи, сквозной пример и **реестр фактов с цитатами** — `videos/<имя>/v4/brief.json` (`essence`,
`running_example`, `facts`); у каждой сцены в плане — `fact_ids`. Статья — `videos/<имя>/reel/paper.pdf`.

## 2. Придумать сцены

Сначала составь для себя план всего ролика: для каждой сцены — фраза диктора, одна метафора, главное
событие и слово, на котором оно случается. Хорошо работает **сквозной предмет**, который живёт через
несколько сцен (пост с форума, письмо, молекула, база, перевал энергии) и меняется по ходу истории.

Типовые беды серверных роликов, которые надо исправлять:
- одна и та же схема (`diagram`) в половине сцен, а заголовок схемы налезает на её блоки;
- мелкие кропы статьи с английским текстом, который никто не прочтёт;
- ключевое слово фразы попадает на стоковую видеовставку, а не на объясняющую анимацию;
- заглушки «ГЕНЕРАЦИЯ» вместо несгенерированных вставок;
- числа без образа: «5 из 123» лучше показать точками, «вдвое» — двумя столбиками.

Настоящие видеовставки (`reel/media/*.mp4`) можно оставить в 1–3 сценах для дыхания: сцена без своего
файла в `work/` остаётся как была.

## 3. Написать шоты

Один файл на сцену: `videos/<имя>/work/<сцена>.js` — тело функции шота (без `SH.x = () => {`).
Настройки — `videos/<имя>/work/plan.json`:

```json
{"kits": ["core", "chem"], "drop": [], "order": null}
```

- `kits` — наборы помощников из `kit/`: `core` (всегда), `chem` (молекулы, энергетический профиль);
- `drop` — сцены, которые выкинуть (например, без голоса); `order` — новый порядок сцен (текст сцен менять нельзя);
- сцена из нескольких шотов: файлы `<сцена>_1.js`, `<сцена>_2.js` и `"split": {"s3": [0.6, 0.4]}`.

**Перед первым шотом прочитай** `docs/shot_api.md` (API движка и наборов, ловушки) и 2–3 файла из
`examples/` — это проверенные шоты из готовых роликов. Начинай с их копии и меняй под свою сцену.

Время: `Wv('слово', запасное_время)` — когда диктор говорит слово (от начала шота). Главное событие —
на слове, которое его называет. Что-то меняется каждые 1–1,5 с. Последняя строка шота — `exitAll();`.

## 4. Проверить и посмотреть

```bash
python3 scripts/check.py videos/<имя>             # сборка плана + DOM-проверка всех шотов
python3 scripts/stills.py videos/<имя> 's3_|s7_'  # кадры 30/62/93 % -> videos/<имя>/review/stills_N.png
```

Строки «!!» чини обязательно. **Всегда смотри листы кадров сам** (открой PNG) до того, как показывать
человеку: наложения, обрезка краем, пустой кадр, мелкий текст, элемент, который виден раньше времени.

## 5. Собрать ролик

```bash
bash scripts/build.sh videos/<имя>     # -> videos/<имя>/out/reel_<имя>.mp4 и reel/contact_sheet.jpg
```

Посмотри новый `contact_sheet.jpg`, отдай человеку mp4. Если сомневаешься в идее сцены — сделай
второй вариант: `cp -r videos/<имя> videos/<имя>_B`, поменяй файлы сцены в `_B/work/`, собери оба.

## Правила (не нарушать)

- **Дизайн фиксирован** (стиль Apple): светлый фон, белые карточки `Kc`, шрифт Inter `Tx`, **один акцент —
  синий** `A.blue`; красный `A.red` и зелёный `A.green` — только «неверно / верно» (или «опасно / безопасно»),
  янтарный `A.amber` — «сомнительно». Без градиентов, эмодзи и пестроты.
- Безопасная зона стейджа x 100–980, y 140–950; ничего не режется краем. Подписи ≥ 28 px, ничего мельче 24 px.
- **Числа на экране — только из фразы диктора или из статьи** (`brief.json` → `facts`, `paper.pdf`). Ничего не
  придумывать. Если для наглядности нужна шкала (например, «1 Вт·ч»), она должна следовать из фразы.
- Реальных людей не рисовать (только абстрактные значки `person`). Текст статьи показывать как есть или
  честным пересказом; придуманные для примера фразы — явно как иллюстрацию.
- Надписи 2–5 слов, по-русски, не пересказывают фразу: экран показывает, голос объясняет.
- Текст сцен, голос, аватар — не трогать. `reel/shot_plan.orig.json` не редактировать: план всегда
  собирается заново из него и твоих файлов.
